# ClayAway — нотатки для програмістів

Це **проєкт** нового напряму ClayArena, зібраний як статичний сайт для обговорення і передачі в розробку.
Усе тут — робоча специфікація + працюючі макети. Далі програмісти переносять це в ClayArena (backend, БД,
адмінка, авторизація, платежі). Цей файл пояснює, що є що, як воно працює і що треба зробити для продакшену.

> Мова коду й даних — англійська (ідентифікатори, ключі). Тексти інтерфейсу — UA/EN. Російську мову не використовуємо.
> Повні ТЗ: `docs/concept/` (тури ClayAway) і `docs/rules-spec/` (правила FITASC, тренажер, глосарій, SEO, легальність).

## 2. Як запустити локально

```bash
python -m http.server 8792 --bind 127.0.0.1 --directory docs
```
Відкрити http://127.0.0.1:8792/ . Збірки: `bun scripts/build_seo.mjs`, `python scripts/make_og.py`, `python scripts/seo_meta.py`.
Порядок після зміни даних правил: `build_seo.mjs` → `make_og.py` → `seo_meta.py`.

## 3. Тури ClayAway → ClayArena

Сторінки `docs/dornsberg|sologne/index.html` — один файл = HTML + CSS + JS. Дані туру зараз у константах JS
(`TOURS`, `MEDIA`, `GLANCE`, `MEALS`, `MEALPHOTOS`); у продакшені це відповіді API. Відповідність:

| Константа в макеті | Сутність / таблиця в ClayArena (див. ТЗ «Сутності й поля») |
|---|---|
| `TOURS[t]` (title, dates, places, booked, min, price, options, langs, about, program, included, cancel, faq…) | `Tour`, `PriceOption`, `ItineraryDay`, `ItineraryItem`, переклади полів по мовах туру |
| `TOURS[t].people` | `TourMember` (ролі: Organizer, Coach, Staff:Interpreter…) + профілі ClayArena (тренер, стрілець, стенд) |
| `TOURS[t].qa` | публічні питання (відкрита зона спілкування), модерація |
| `TOURS[t].announcements`, `chat` | закрита зона групи — **через існуючі інструменти спілкування ClayArena** |
| `TOURS[t].participants`, `todo`, `inbox` | `Booking`, `Payment`, задачі кабінету організатора |
| `MEDIA` | медіа туру: відео ClayArena (cdn.clayarena.com), фото, embed соцмереж |
| `GLANCE` | блок «The tour at a glance»: спорт / трансфер / кухня / ≤50 км / готель |
| `MEALS`, `MEALPHOTOS` | `ItineraryItem(type=meal)` з `meal_kind`, `included`, `together`, `venue`, `cuisine_note` |

Обовʼязково на сервері (у макеті імітується в браузері):
- **Місця**: утримання місця 15 хв під час оплати (транзакція/lock), лічильник вільних місць, лист очікування.
- **Доступ**: закрита зона групи тільки для підтверджених оплачених бронювань; видимість полів за роллю перевіряє сервер.
- **Оплата**: через ClayArena, split-платежі (наприклад Stripe Connect), комісія ClayArena — % від виплати організатору.
- **Мови**: кожне текстове поле туру — окремо на кожній увімкненій мові; EN обовʼязкова.
- **SEO**: див. ТЗ турів, розділ «SEO, розмітка і превʼю» (Event + Offer JSON-LD, OG-картинка з обкладинки).

## 4. Довідник правил і тренажер → ClayArena

- Дані: `docs/rules/data/sporting.js`, `compak.js` (книга → розділи → пункти → FAQ), `quiz-*.js` (питання з `refs` на пункти).
  У БД: `rule_books`, `rule_sections`, `rule_items`, `rule_faq`, `rule_quiz_questions`, `glossary_terms`; поле `edition` для версій.
- Пошук зараз — клієнтський (TF-IDF-подібний, словник синонімів UA/EN у `docs/rules/index.html`, функції `expand`, `search`).
  Етап 2: `POST /api/rules/ask` → пошук пунктів на сервері → Claude API відповідає **лише** з цих пунктів, з `ref`/сторінками.
- Тренажер: прогрес у `localStorage` → у продакшені в профілі користувача (+ бейдж, статистика складних питань).
- Оновлення FITASC: GitHub Action → задача → оновлення даних → погодження суддею → `fitasc_check.py --accept`.

## 5. Легальність (коротко; повністю — ТЗ, блок «Легальність контенту і права»)

- Текст і PDF FITASC не публікуємо; лише власний переказ + посилання `rel="nofollow noopener noreferrer"`.
- Фото зі сторонніх сайтів (стенди) — у проєкті тимчасово для внутрішнього показу; перед публічним запуском замінити або отримати дозвіл.
- Фото Wikimedia — з автором і ліцензією в «Photo credits».
- Реальні люди в прикладах — тільки за згодою; демо-тури `noindex`.
